# Code of Conduct

## Our standard

This is a three-person team building a safety-adjacent tool on a deadline. We
hold each other to two things: treat people with respect, and be honest about
what the data supports.

Expected behavior:

- Give direct, specific, kind feedback in code review.
- Assume a teammate's confusion is a documentation problem, not a competence
  problem.
- Say "I don't know" early rather than late.
- Ask before reworking someone else's deliverable.

Unacceptable behavior:

- Harassment, discrimination, or demeaning remarks of any kind.
- Publishing a claim the evidence does not support, or overstating a result to
  make a demo land better. For a tool that speaks about traveler safety, this
  is a conduct issue and not only a technical one.
- Dismissing a limitation because acknowledging it is inconvenient.

## Scope

Applies to the repository, pull requests, issues, team channels, and any venue
where we represent the project — including the Carolina Data Challenge
presentation and the DevPost submission.

## Reporting

Raise concerns with any teammate. If a concern involves a teammate, escalate to
the Carolina Data Challenge organizers. Reports are handled discreetly.
